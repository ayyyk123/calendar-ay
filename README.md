# 캘린더 v1.15


## v1.18 변경사항

- 날짜 지정 고정업무는 해당 월에 한 번 배치되면 **✓ 배치완료**로 회색 비활성화되며 더 이상 드래그되지 않습니다.
- 달력에서 그 배치 일정을 삭제하면 고정업무가 자동으로 다시 활성화됩니다.
- 일정 수정창에 **↪ 다음날로 이어하기** 기능을 추가했습니다.
- 이월할 때 남은 예상 소요시간을 입력하면 다음날 동일 캘린더에 별도 일정으로 등록됩니다.
- 원래 날짜 일정에는 **부분완료 · 이월**, 다음날 일정에는 **↪ 전날 미완료** 배지가 표시됩니다.
- 계속 이월하면 **↪ 2일째 이월, ↪ 3일째 이월**처럼 누적 표시됩니다.
- 이월 일정은 원래 캘린더 색을 유지하고 점선/배지로만 구분해 캘린더 소속을 헷갈리지 않게 했습니다.

주간 화면 중심의 개인 일정/업무량 관리 웹앱입니다.

## v1.16 변경사항
- 새 부속캘린더에서 `상위 캘린더`를 선택하면 상위 캘린더와 같은 색 계열의 추천색을 자동 적용합니다.
- 하위 캘린더가 여러 개이면 같은 색상 계열을 유지하면서 밝기·채도를 조금씩 달리해 서로 구분합니다.
- 이미 만들어진 캘린더의 색상은 상위 캘린더를 바꿔도 임의로 덮어쓰지 않습니다. 필요할 때 `상위색 계열 추천` 버튼을 눌러 다시 추천받을 수 있습니다.
- 추천색이 마음에 들지 않으면 기존처럼 색상 선택창에서 자유롭게 수정할 수 있습니다.
- v1.14의 최신자료 저장, 부속캘린더, Firebase 자동동기화, 저장상태, 백업/복원, 공휴일, 월~일 배열, 상세 반복 일정 및 업무량 관리 기능을 모두 유지합니다.

## 데이터 저장
자동 저장과 별개로 상단 `최신자료 저장`을 누르면 현재 기기 데이터를 먼저 저장한 후 Firebase에 즉시 저장을 시도합니다. 상단 저장 상태에서 성공 시각을 확인할 수 있습니다.

## 백업
설정(⚙) → 데이터 백업 → `백업 다운로드`를 누르면 전체 캘린더 데이터를 JSON 파일로 저장합니다. `백업 불러오기`로 복원하면 현재 로그인 계정의 Firebase에도 같은 데이터가 저장됩니다.

## Firebase 보안 규칙
Firestore Console → 규칙(Rules)에 `firestore.rules` 내용을 붙여넣고 게시하세요. 로그인한 사용자가 자신의 `users/{uid}/...` 데이터만 읽고 쓸 수 있도록 제한합니다.

## v1.16 추가 변경사항
- 매월 고정업무 드래그가 금지 표시로 막히던 문제를 수정했습니다. 표준 text/plain 드래그 페이로드와 앱 내부 드래그 상태를 함께 사용해 주간/월간/일간 날짜 칸에 안정적으로 놓을 수 있습니다.
- 드래그 중 놓을 수 있는 날짜 칸은 파란 점선으로 표시됩니다.
- 왼쪽 `매월 고정업무` 영역을 `매월 자동반복(달력에 이미 배치)`와 `날짜 지정 배치(드래그해서 넣기)` 두 목록으로 분리했습니다.
- 두 목록은 각각 접기/펴기가 가능하며 상태가 Firebase 설정 데이터에 함께 저장됩니다.
- 매월 자동반복 목록은 클릭하면 해당 반복 일정을 수정할 수 있고, 날짜 지정 배치 목록은 기존처럼 더블클릭해서 원본 업무를 수정할 수 있습니다.
